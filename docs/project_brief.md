## 1. Карточка аналитической задачи

### 1.1. Предметная область и контекст

Рассматривается почасовой спрос на городской велопрокат Seoul Bike в Сеуле. В наборе данных для каждого часа указаны число арендованных велосипедов, температура воздуха, сезон, календарные признаки и другие погодные показатели.

Для проекта интерес представляет связь температуры со спросом. При этом один и тот же уровень температуры может сопровождаться разным спросом утром, днём или вечером, а характер связи может отличаться в разные сезоны. Поэтому температура рассматривается совместно со временем суток и сезонностью.

Задача является описательной: данные позволяют определить, как связаны температура и наблюдаемый спрос, но не позволяют доказать, что изменение температуры само по себе является причиной изменения числа аренд.

### 1.2. Цель анализа

Определить, как временная структура спроса на велопрокат связана с погодными условиями и сезонностью.

### 1.3. Аналитические вопросы

**Основной вопрос.**

Как меняется связь температуры со спросом на велопрокат в зависимости от времени суток?

**Уточняющий вопрос 1.**

Одинаков ли характер этой связи в разные сезоны?

## 5. Ограничения и будущие проверки качества

### 5.1. Ограничения набора

- Набор содержит только один год наблюдений. Поэтому результаты описывают период с декабря 2017 по ноябрь 2018 года и не гарантируют повторение тех же закономерностей в другие годы.
- Анализ показывает статистическую связь, а не причинный эффект. Например, высокий спрос при более высокой температуре может одновременно быть связан с сезоном, осадками, рабочим днём и другими факторами.
- Температура и сезон естественно связаны между собой. Зимой и летом диапазоны температур почти не совпадают, поэтому общий коэффициент корреляции нужно дополнять сезонным сравнением.
- Коэффициент корреляции Пирсона описывает прежде всего линейную связь. Если зависимость окажется явно нелинейной, в следующих работах можно дополнительно использовать, например, температурные интервалы.
- Часы `Functioning Day = No` имеют нулевой спрос из-за недоступности сервиса. Для анализа связи погоды с пользовательским спросом такие строки исключаются.
- Набор агрегирован до уровня одного часа по системе в целом и не содержит данных об отдельных пользователях или поездках. Поэтому нельзя делать выводы об индивидуальном поведении конкретного пользователя.
- Другие погодные поля присутствуют, но в текущем вопросе не анализируются, чтобы не усложнять работу без необходимости.

### 5.2. Гипотезы о проверках качества

| Гипотеза о качестве. | Как её можно проверить. | Почему это важно для задачи. |
| --- | --- | --- |
| Каждая пара `Date + Hour` уникальна. | Проверить `duplicated(['Date', 'Hour'])`. | Дублирование часов исказит средний спрос и корреляцию. |
| Для каждой даты представлены все 24 часа. | Сгруппировать по дате и проверить количество уникальных часов. | Неполные сутки могут нарушить временную структуру данных. |
| `Rented Bike Count` неотрицателен. | Проверить количество значений `< 0`. | Отрицательное число аренд не имеет физического смысла. |
| Ключевые поля не содержат пропусков. | Проверить `isna()` для спроса, температуры, часа, сезона и признака работы. | Пропуски изменят число наблюдений в группах и могут исказить корреляцию. |
| `Hour` находится в диапазоне 0–23. | Проверить минимум, максимум и значения вне диапазона. | Ошибочный час создаст неправильный временной срез. |
| `Seasons` содержит только четыре ожидаемые категории. | Проверить `unique()` / `value_counts()`. | Ошибочные категории создадут ложные сезонные группы. |
| Неработающие часы имеют нулевой спрос. | Для `Functioning Day = No` проверить `Rented Bike Count == 0`. | Это подтверждает необходимость исключить их из анализа пользовательского спроса. |

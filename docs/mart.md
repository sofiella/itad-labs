# Аналитическая витрина Seoul Bike Sharing Demand

## 1. Модель

**Аналитический вопрос:** как меняется связь температуры со спросом на велопрокат в зависимости от времени суток?

Для анализа подготовлена витрина `hourly_rentals` на основе нормализованных данных из ЛР №3.

Одна строка витрины соответствует одному часу конкретной календарной даты. Составной ключ — `event_date` и `hour_of_day`. При проверке ключа пропусков и повторов не обнаружено.

Основная мера — `rented_bike_count`, количество арендованных велосипедов за час. Значения можно суммировать по непересекающимся временным интервалам. Поле `temperature_c` содержит температуру воздуха в градусах Цельсия и используется для сравнения со спросом. Температурные значения не суммируются.

Для ответа на аналитический вопрос предполагается рассчитывать средний почасовой спрос и корреляцию температуры с количеством аренд отдельно для каждого часа суток. Число наблюдений определяется через `COUNT(*)`, при этом оно не равно числу арендованных велосипедов.

В качестве основного среза используется `hour_of_day`. Поле `functioning_day` позволяет исключать нерабочие часы при дальнейшем расчёте показателей.

Витрина представлена одной широкой таблицей. Дополнительные таблицы измерений не создавались, поскольку все необходимые поля уже присутствуют в `staging`. Исходная гранулярность сохранена.

## 2. Сопоставление полей

| Поле витрины | Поле в staging | Преобразование | Назначение |
|---|---|---|---|
| `event_date` | `event_date` | Без изменений | Дата наблюдения |
| `hour_of_day` | `hour_of_day` | Без изменений | Час суток, от 0 до 23 |
| `rented_bike_count` | `rented_bike_count` | Без изменений | Количество аренд за час |
| `temperature_c` | `temperature_c` | Без изменений | Температура воздуха, °C |
| `functioning_day` | `functioning_day` | Без изменений | Статус работы проката |
| `quality_non_functioning_hour_violated` | `quality_non_functioning_hour_violated` | Без изменений | Флаг нерабочего часа из ЛР №3 |

Витрина сохранена в формате Parquet:

`s3://mart/seoul-bike-sharing-demand/source_ingested_on=2026-09-30/hourly_rentals.parquet`

Логическая дата загрузки сохранена из пути исходного `staging` и не используется как дата наблюдения.

## 3. Проверки и ограничения

SQL-запросы и результаты проверок приведены в ноутбуке [build_mart.ipynb](../notebooks/build_mart.ipynb), в разделах 4 и 5.

Во входном `staging` содержится 8760 строк. После сборки и сохранения витрины количество строк не изменилось. Все записи перенесены без фильтрации.

Проверка сохранённого Parquet-файла показала:

- Пропусков в составном ключе и обязательных полях нет.
- Повторяющихся сочетаний даты и часа нет.
- Некорректных значений часа и отрицательного количества аренд нет.
- Количество аренд находится в диапазоне от 0 до 3556, температура — от −17,8 до 39,4 °C.
- В `staging` и витрине сохранено по 295 записей с флагом нерабочего часа.
- Расхождений между флагом качества и статусом работы проката нет.
- Сравнение данных через `EXCEPT ALL` не выявило отсутствующих, лишних или изменённых записей.

Контрольная группировка работающих часов по `hour_of_day` вернула 24 группы и 8465 наблюдений. В каждой группе содержится от 352 до 353 записей. Это подтверждает возможность дальнейшего сравнения спроса в разные часы суток.

Основное ограничение заключается в наличии 295 нерабочих часов. Они сохранены в витрине согласно решению ЛР №3, но при анализе спроса должны исключаться. Данные охватывают период с 01.12.2017 по 30.11.2018 и позволяют исследовать статистическую связь температуры со спросом, но не доказывают причинно-следственную зависимость.
